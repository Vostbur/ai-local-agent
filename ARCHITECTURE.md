# Архитектура

## Общая схема
Пользователь ставит цель.
Оркестратор передаёт цель локальной LLM.
LLM выбирает инструмент и аргументы.
Оркестратор вызывает инструмент.
Результат возвращается в LLM.
Цикл повторяется до достижения цели или лимита шагов.

## Компоненты

### Оркестратор
- Управляет циклом «рассуждение → действие → наблюдение».
- Ограничивает число шагов.
- Логирует каждый шаг.
- Поддерживает режим подтверждения опасных действий.

### Локальная LLM
- Работает через Ollama или llama.cpp.
- На шаге MVP используется текстовая модель 3–7B в квантовании Q4.
- Мультимодальная модель подключается позже для фото.

### Реестр инструментов
- Каждый инструмент описан: имя, назначение, аргументы, возвращаемое значение, побочные эффекты.
- Агент не пишет код инструментов. Он выбирает из зарегистрированных.
- Новые инструменты добавляются вручную и проходят тесты.

### Память
- Краткосрочная: контекст текущей задачи.
- Долгосрочная: заметки, индекс документов, история действий.
- Векторная база: ChromaDB или FAISS, позже.

### Логи
- Каждый запрос к LLM, вызов инструмента и результат пишутся в `logs/`.
- Логи нужны для отладки и оценки скорости на CPU.

## Инструменты MVP
1. `save_note(title, content)` — сохранить заметку в Markdown.
2. `read_notes(query)` — найти заметки по запросу.
3. `extract_pdf_text(path)` — извлечь текст из PDF.
4. `search_documents(query)` — поиск по проиндексированным документам.
5. `analyze_image(path, question)` — анализ изображения локальной мультимодальной моделью.
6. `move_file(src, dst)` — переместить файл с подтверждением.

## Ограничения MVP
- Только один агент.
- Без самодописывания кода.
- Файловые операции только с подтверждением и возможностью отмены.
- Лимит шагов на задачу: 10.
