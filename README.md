# AI Local Agent

Локальный AI-агент для повседневных задач. Работает полностью на вашем компьютере: ни документы, ни заметки, ни фотографии не покидают вашу машину.

## Что умеет сейчас

- **Сохранять заметки** в Markdown-файлы (`save_note`) — в корень `data/notes/` или в категорию (подпапку). Существующие заметки никогда не перезаписываются: при совпадении имени добавляется числовой суффикс.
- **Искать заметки по названию** (`read_notes`) — по заголовку и имени файла, с учётом русских словоформ.
- **Искать по содержимому заметок** (`search_notes`) — с фрагментом контекста и числом совпадений.
- **Показывать заметки списком** (`list_notes`) — все или из одной категории, с датой изменения и размером.
- **Изменять заметки** (`update_note`) — заголовок и/или текст; файл не переименовывается и не перемещается.
- **Удалять заметки** (`delete_note`) — в корзину `data/trash/notes/`, не физически: структура категорий сохраняется, к имени файла добавляется таймстамп.
- **Перемещать заметки между категориями** (`move_note`) — при конфликте имён в целевой категории добавляется суффикс `_1`, `_2`.
- **Показывать категории** (`list_categories`) — подпапки `data/notes/` с числом заметок в каждой.
- **Принимать заголовок вместо пути** в `update_note` / `move_note` / `delete_note`: если файла по указанному пути нет, инструмент ищет заметку по заголовку (см. «Работа с заметками»).
- **Искать по документам** (`search_documents`) — семантический поиск по Markdown, TXT, PDF и DOCX в `data/documents/`. Гибридный поиск: BM25 (лексический) + векторный (эмбеддинги) через RRF. Находит по смыслу, а не только по точному слову.
- **Читать документ целиком** (`read_document`) — Markdown, TXT, PDF, DOCX, с обрезкой до `max_chars`.
- **Создавать документ по шаблону** (`write_document`) — прочитать шаблон через `read_document`, сгенерировать новый по структуре, сохранить в `data/generated/`.
- **Чат с моделью без инструментов** (`python -m agent ask "вопрос"`) — прямое обращение к LLM, как `ollama run`, без SYSTEM_PROMPT и без tools. Интерактивный режим (без аргумента) помнит контекст диалога в пределах сессии.
- **Помнить контекст диалога** в `chat`, интерактивном `ask` и веб-чате: уточнения вида «перенеси её в категорию Покупки» или «а подробнее?» понимаются без повторения предыдущих условий. История ограничена: последние 10 сообщений, суммарно до 4000 символов (защита контекста 7B от переполнения).
- **Работать через браузер** (`python -m agent web`): вкладка «Агент» (задачи с инструментами, SSE-прогресс по шагам, отмена задачи кнопкой «стоп»), «Документы» (поиск по RAG-корпусу и переиндексация), «Чат» (без инструментов). История чата и активная задача переживают переключение вкладок и перезагрузку страницы.
- **Отменять выполняющуюся задачу** в веб-интерфейсе: во время генерации кнопка отправки превращается в кнопку «стоп» (тот же цвет, иконка квадрата). То же доступно через `POST /cancel/{task_id}`.
- **Работать с локальной моделью** через [Ollama](https://ollama.com) — по умолчанию 7B, 3B как опция для скорости.
- **Не вызывать инструменты зря:** на посторонние вопросы вроде «какая погода» агент отвечает без `tool_call`.
- **Не зацикливаться на повторных вызовах:** одинаковый вызов инструмента с теми же аргументами пропускается. После `max_tool_failures` неудач подряд падающий вызов блокируется.
- **Не зависеть от текущей папки:** конфиг и данные берутся от корня проекта, а не от CWD.
- **Переживать `null` в опциональных аргументах от модели.**
- **Вести логи своих действий** в `logs/agent.log` — без полных текстов заметок и документов.

## Требования

- Операционная система: Windows 10/11, macOS или Linux.
- Python 3.11 или новее. Проверено на 3.11, 3.12, 3.13.
  - Скачать: https://www.python.org/downloads/
  - На Windows при установке обязательно поставьте галочку «Add Python to PATH».
- Ollama. Скачать: https://ollama.com/download
  - После установки Ollama запускается автоматически. Если нет — откройте терминал и выполните `ollama serve`.
- Свободное место на диске: около 7 ГБ (7B-модель ~5 ГБ + зависимости ~2 ГБ).
- Оперативная память: 16 ГБ рекомендуется (7B-модель занимает ~6 ГБ). На 8 ГБ будет тесно.
- Git (по желанию, но рекомендуется). Скачать: https://git-scm.com/downloads

## Выбор модели: 3B или 7B

|  | 3B | 7B |
| --- | --- | --- |
| Скорость (CPU) | 1–2 мин на вопрос | 2–4 мин на вопрос |
| RAM | ~2–3 ГБ | ~6 ГБ |
| Диск | ~2 ГБ | ~5 ГБ |
| Routing инструментов | 4/7 (путает `search_documents` / `search_notes`, пустые финалы) | 7/7 |
| Рекомендация | если критична скорость | по умолчанию |

По умолчанию `settings.example.toml` использует 7B. Чтобы переключиться на 3B:

```bash
ollama create qwen2.5-3b-agent -f Modelfile
```

И в `config/settings.toml`:

```toml
[llm]
model = "qwen2.5-3b-agent"
```

## Установка с нуля (для новичка)

Все команды ниже выполняются в терминале. На Windows удобно использовать PowerShell, на macOS/Linux — Terminal.

### Шаг 1. Скачайте проект

Если вы уже скопировали папку проекта — переходите к шагу 2. Иначе:

```bash
git clone <адрес-вашего-репозитория> ai-local-agent
cd ai-local-agent
```

Если git не установлен, скачайте архив с проектом и распакуйте его, затем откройте терминал в распакованной папке.

### Шаг 2. Установите Ollama и загрузите модель

Установите Ollama с официального сайта.

Убедитесь, что Ollama работает:

```bash
ollama --version
```

Если команда не найдена — перезапустите терминал.

Загрузите модель:

```bash
ollama pull qwen2.5:7b
```

Займёт несколько минут и около 5 ГБ.

Проверьте:

```bash
ollama run qwen2.5:7b "Привет"
```

Выйти из интерактивного режима — Ctrl+D (macOS/Linux) или `/bye` (Windows).

### Шаг 3. Создайте модель с увеличенным контекстом

В корне проекта уже есть `Modelfile.7b` (для 7B) и `Modelfile` (для 3B). Соберите модель под новым именем:

```bash
ollama create qwen2.5-7b-agent -f Modelfile.7b
```

Проверьте:

```bash
ollama list
```

В списке должна появиться `qwen2.5-7b-agent:latest` (тег `:latest` Ollama добавляет автоматически).

### Шаг 4. Создайте виртуальное окружение Python

```bash
python -m venv .venv
```

Активируйте:

Windows (PowerShell):

```powershell
.venv\Scripts\Activate.ps1
```

Если PowerShell ругается на политику выполнения, один раз выполните:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Windows (cmd):

```cmd
.venv\Scripts\activate.bat
```

macOS / Linux:

```bash
source .venv/bin/activate
```

В начале строки появится `(.venv)`.

### Шаг 5. Установите проект в режиме разработки

```bash
pip install -e .
```

Это установит зависимости (`requests`, `pymupdf`, `sentence-transformers`, `numpy`) и зарегистрирует пакет `agent` — после этого работают обе формы:

```bash
python -m src.agent --help
python -m agent --help
```

Вторая короче, рекомендуется. Первая работает без `pip install -e .`, если запускать из корня проекта.

Первый запуск `python -m agent index` скачает модель эмбеддингов `paraphrase-multilingual-mpnet-base-v2` (~1.1 ГБ) — только когда вы соберёте RAG-индекс.

### Шаг 6. Создайте локальный файл настроек

```bash
# macOS / Linux
cp config/settings.example.toml config/settings.toml
```

```powershell
# Windows (PowerShell)
Copy-Item config\settings.example.toml config\settings.toml
```

Файл `config/settings.toml` не попадает в git — это ваши личные настройки.

### Шаг 7a. Проверьте, что всё работает

```bash
pytest -v
```

Все тесты должны быть зелёными. Благодаря `pyproject.toml` с `pythonpath = ["."]` тесты запускаются из любой папки проекта.

Запустите агент с одной задачей (реальная модель):

```bash
python -m agent run "Сохрани заметку 'Тест запуска' с текстом 'Привет'"
```

Первый запуск может занять несколько минут: модель загружается в память, а генерация на CPU медленная. В итоге в `data/notes/` появится файл с заметкой, а в консоли — строка вида `Готово: ...`.

Важно: скрипт можно запускать из любой папки — конфиг и данные ищутся от корня проекта, а не от текущей директории. Например, из `C:\`:

```powershell
python D:\projects\ai-local-agent\scripts\run_agent.py "Покажи все заметки"
```

(`scripts\run_agent.py` — deprecated-обёртка, работает для обратной совместимости. Основная форма — `python -m agent run "..."`.)

### Шаг 7b. Соберите RAG-индекс (опционально)

Если хотите искать по документам:

1. Положите `.md`, `.txt`, `.pdf` или `.docx` файлы в `data/documents/` (можно в подпапки).
2. Соберите индекс:

```bash
python -m agent index --reset
```

Первый запуск скачает модель эмбеддингов (~1.1 ГБ) и построит индекс. Для 50 файлов — 2–5 минут. Для 3000 чанков (например, PDF на 400 страниц) — около 2 минут на CPU.

3. Проверьте, что поиск работает (без LLM):

```bash
python -m agent search "тестовый запрос" --top-k 3
```

## Как пользоваться агентом

Все команды — через `python -m agent <command>`. Если вы не делали `pip install -e .`, используйте `python -m src.agent <command>`.

### `run` — одна задача агенту

```bash
python -m agent run "Сохрани заметку 'Список покупок' с текстом 'Молоко, хлеб, яйца'"
```

Скрипт выполнит цель, напечатает финальный ответ и (если инструмент вернул путь) — путь к созданному файлу.

Если задача не удалась, будет напечатана причина:

```
Не удалось выполнить задачу. Шагов: 1
Причина: empty final answer
```

### `chat` — интерактивный режим

```bash
python -m agent chat
```

Скрипт запустится один раз и будет спрашивать цели одну за другой. Модель остаётся загруженной в память, поэтому следующие задачи выполняются быстрее, чем при повторном запуске.

```
AI Local Agent (модель: qwen2.5-7b-agent)
Введите цель или /quit для выхода.
> сохрани заметку про встречу в понедельник
[...] выполняется, подождите (на CPU это может занять несколько минут)
Готово: Заметка сохранена.
Шагов: 2
> /quit
Выход.
```

Для выхода: `/quit`, `/exit`, `exit`, `quit`, `Ctrl+C` или `Ctrl+D`.

**Память диалога:** в пределах одной сессии `chat` агент помнит предыдущие обмены. После «Создай заметку со списком покупок» можно написать «Перенеси её в категорию Покупки» — агент поймёт, о какой заметке речь (история передаётся вместе с новой целью). Память живёт до выхода; ограничение — последние 10 сообщений (суммарно до 4000 символов).

Холодный старт: первый запрос после долгого перерыва может занять больше пяти минут — модель загружается в память. Это нормально; последующие запросы в той же сессии заметно быстрее.

### `ask` — чат с моделью без инструментов

```bash
python -m agent ask "кто такой Достоевский?"
```

Прямой вызов LLM: без SYSTEM_PROMPT, без tools, без оркестратора. Поведение как `ollama run`. Модель отвечает из pretrained-знаний, инструменты недоступны.

Без аргумента — интерактивный чат **с памятью диалога** (уточняющие вопросы понимаются в контексте предыдущих ответов):

```bash
python -m agent ask
> что такое RAG?
> /quit
```

Когда использовать: общие вопросы (литература, история, код, наука), не связанные с вашим проектом или документами. Для вопросов про проект/документы — `run` с `search_documents`.

Ограничение: 7B на общих знаниях может ошибаться в деталях (например, назвать Достоевского «романтиком»). Это ограничение модели, не проекта.

### `index` — пересборка RAG-индекса

```bash
python -m agent index              # инкрементально (пока не реализовано, работает как --reset)
python -m agent index --reset      # перезаписать существующий индекс
python -m agent index --documents "D:\Knowledge"
python -m agent index --batch-size 64
```

Переиндексация нужна после добавления или изменения документов. Эмбеддинги и чанки не меняются при смене LLM — модель 3B ↔ 7B на индекс не влияет.

Вместе с индексом пересобирается и кэш BM25 (`data/index/bm25.json`), поэтому лексический поиск после переиндексации стартует без задержки на перетокенизацию корпуса.

### `search` — отладка retrieval без LLM

```bash
python -m agent search "OSPF" --top-k 3
python -m agent search "требования" --top-k 5 --no-truncate
```

Показывает, какие чанки находит гибридный поиск (BM25 + векторный) до синтеза ответа. Полезно, если ответ агента кажется нерелевантным: сначала проверьте retrieval, потом вините модель.

### `web` — веб-интерфейс

```bash
python -m agent web
python -m agent web --host 127.0.0.1 --port 8080
```

По умолчанию `--host 0.0.0.0` (доступен по локальной сети) с предупреждением в логе. См. «Безопасность».

Откройте `http://<ip-вашего-компьютера>:8000` в браузере (или `http://127.0.0.1:8000` локально). Вкладки:

- **Агент** — чат с агентом с инструментами (`save_note`, `search_documents`, …). SSE-прогресс по шагам: «Агент думает… → Выполнено: search_documents (5) → ответ». Во время выполнения кнопка отправки превращается в кнопку «стоп» — задача отменяется на сервере (`POST /cancel/{task_id}`). Диалог помнит предыдущие обмены: история последних реплик передаётся с каждым запросом.
- **Документы** — поиск по RAG-корпусу и переиндексация.
- **Чат** — прямой чат с моделью без инструментов (`ask_plain`), с памятью диалога.

История чата и активная задача сохраняются в браузере (`localStorage`): при переключении вкладок или перезагрузке страницы происходит переподключение к SSE-потоку, таймер выполнения не сбрасывается.

**Важно (T41):** после переиндексации (вкладка «Документы» или `python -m agent index`) запущенный веб-сервер продолжает искать по старому индексу до перезапуска. Перезапустите `python -m agent web`, чтобы подхватить новый индекс.

## Типичные проблемы при запуске

- **Ollama не отвечает.** Запустите `ollama serve` в отдельном терминале и повторите.
- **Не найден файл настроек.** Скопируйте `config/settings.example.toml` в `config/settings.toml`.
- **Достигнут лимит шагов.** Модель не смогла дойти до финала за `max_steps` шагов. Сформулируйте цель точнее или увеличьте `max_steps` в `config/settings.toml`.
- **`FileNotFoundError: index not found`.** RAG-индекс не собран. Выполните `python -m agent index --reset`.
- **Первый запрос в сессии очень долгий.** Холодный старт модели на CPU (>5 минут). Повторите запрос — модель уже в памяти.
- **Поиск по заметкам ничего не находит, хотя текст есть.** Особенности стеммера (см. «Работа с заметками», ограничение): переформулируйте запрос словом из текста заметки.
- **Веб-поиск по документам возвращает старые результаты после переиндексации.** Запущенный сервер держит индекс в памяти (T41). Перезапустите `python -m agent web`.

## Где хранятся данные

- Заметки: `data/notes/` — по категориям: `data/notes/<категория>/<заметка>.md`, без категории — в корне `data/notes/`.
- Корзина заметок: `data/trash/notes/` — структура категорий сохраняется, к имени файла добавляется таймстамп `ГГГГММДД_ЧЧММСС_`.
- Документы для RAG: `data/documents/`
- Векторный индекс: `data/index/` (`vectors.npy`, `chunks.json`, `meta.json`)
- Кэш BM25: `data/index/bm25.json` — обратный индекс лексического поиска; пишется при сборке индекса, загружается при старте без перетокенизации чанков; инвалидируется автоматически при любом изменении корпуса (манифест содержимого).
- Сгенерированные документы: `data/generated/` (по шаблону через `write_document`)
- Логи: `logs/agent.log`
- Настройки: `config/settings.toml`

Пути резолвятся от корня проекта, а не от текущей папки. Папки `data/` и `logs/` не попадают в git — ваши личные данные не окажутся в репозитории.

## Работа с заметками

Агент работает с заметками в `data/notes/` через восемь инструментов:

| Инструмент | Что делает | Когда используется |
| --- | --- | --- |
| `save_note` | Сохраняет новую заметку в Markdown, опционально в категорию (подпапку). Никогда не перезаписывает: при совпадении имени добавляет `_1`, `_2`. | «Сохрани заметку…», «Запиши…», «Создай заметку в категории Работа» |
| `read_notes` | Ищет по названию (заголовку и имени файла). | «Найди заметку с заголовком…», «Есть ли заметка под названием…» |
| `search_notes` | Ищет по содержимому. Возвращает фрагмент с контекстом и число совпадений. | «Найди, что я писал про…», «В какой заметке упоминается…» |
| `list_notes` | Список заметок: все или из одной категории. | «Покажи все заметки», «Заметки в категории Работа» |
| `update_note` | Меняет заголовок и/или текст существующей заметки. | «Измени заметку…», «Замени текст заметки на…» |
| `delete_note` | Перемещает заметку в корзину (не стирает физически). | «Удали заметку…» |
| `move_note` | Перемещает заметку в другую категорию или в корень. | «Перемести заметку в категорию Архив» |
| `list_categories` | Список категорий с числом заметок. | «Какие у меня категории заметок» |

`max_results` в `read_notes` / `search_notes` / `list_notes` опционален. Если модель передаёт `null` — подставляется дефолт. Если `<= 0` — возвращается пустой список.

Правило маршрутизации (закреплено в системном промпте): вопрос про заголовок/название — `read_notes`; про содержимое — `search_notes`; про категорию или список — `list_notes`.

**Контракт путей.** Все инструменты заметок возвращают пути относительно `data/notes/` в POSIX-формате, например `работа/вторая.md`. Такой путь можно сразу передать в `update_note` / `move_note` / `delete_note`.

**Фолбэк по заголовку.** 7B устойчиво передаёт заголовок заметки вместо пути и не исправляется после ошибки (см. `TODO.md`, C9). Поэтому `update_note` / `move_note` / `delete_note` переживают заголовок в `path`: если файла по пути нет, выполняется поиск заметки по заголовку. Ровно одно совпадение — используется; несколько — ошибка со списком кандидатов; ноль — направляющая ошибка.

**Категории.** Категория — подпапка в `data/notes/`. Имя проходит валидацию: запрещены `..`, `/`, `\` и зарезервированные имена Windows (`CON`, `NUL`, `COM1`…). Пустая строка или `null` в `category` означает корень (без категории).

**Корзина.** `delete_note` перемещает файл в `data/trash/notes/<категория>/<таймстамп>_<имя>`. Восстановление — вручную (вернуть файл в `data/notes/`).

**Ограничение поиска по содержимому (стеммер, см. `TODO.md` C10).** Стеммер работает по префиксу 5 символов со всей строки запроса: многословный запрос «текст два» матчит все заметки со словом «текст»; словоформы, где окончание меняет 5-й символ («единый» ≠ «единого»), не склеиваются. Совет: формулируйте запрос словом из текста заметки — «контракт» найдёт «контракта».

## Работа с документами (RAG)

Агент ищет по Markdown, TXT, PDF и DOCX в `data/documents/` через `search_documents`.

| Шаг | Команда |
| --- | --- |
| 1. Положить документы | Скопировать `.md` / `.txt` / `.pdf` / `.docx` в `data/documents/` (можно в подпапки) |
| 2. Собрать индекс | `python -m agent index --reset` |
| 3. Спросить | `python -m agent run "Что в документах про OSPF?"` |

Переиндексация нужна только после добавления или изменения документов. Эмбеддинги и чанки не меняются при смене LLM.

**Кэш BM25 (T39).** При сборке индекса рядом с `vectors.npy` и `chunks.json` записывается `data/index/bm25.json` — готовый обратный индекс лексического поиска. При старте сервера или CLI он загружается за миллисекунды вместо перетокенизации всех чанков. Кэш защищён манифестом содержимого чанков: любое изменение корпуса (пересборка, правка текста) или ручная порча файла приводит к тихой пересборке индекса в памяти — поиск не сломается.

Отладка поиска без LLM:

```bash
python -m agent search "OSPF" --top-k 3
```

Показывает, какие чанки находит гибридный поиск (BM25 + векторный) до синтеза ответа.

## Как это устроено

**Извлечение.** `src/agent/extractors/` — реестр экстракторов:

- `MarkdownExtractor` (`.md`): режет по заголовкам `#`, убирает code blocks, ссылки, изображения, HTML-теги.
- `TxtExtractor` (`.txt`): один сегмент.
- `PdfExtractor` (`.pdf`): страница → сегмент с `section="Страница N"`; страницы без текстового слоя (сканы) пропускаются.
- `DocxExtractor` (`.docx`): подключён через тот же реестр экстракторов (`register(...)`), RAG не менялся.

Новый формат = новый модуль + одна строка `register(...)` в `src/agent/extractors/__init__.py`. RAG не меняется.

**Чанкинг.** `src/agent/rag/chunker.py` — режет сегменты на куски по 400 символов с перекрытием 100. Старается не рвать на полуслове.

**Эмбеддинги.** `src/agent/rag/embedder.py` — модель `paraphrase-multilingual-mpnet-base-v2` (768-dim, мультиязычная). Ленивая загрузка: модель грузится только при первом поиске или сборке индекса.

**Хранение.** `src/agent/rag/store.py` — `data/index/vectors.npy` + `chunks.json` + `meta.json` + `bm25.json` (кэш BM25). Простое numpy-хранилище, без ChromaDB. Для 100 000+ чанков — миграция на faiss.

**Поиск.** `src/agent/rag/bm25.py` — BM25 (лексический, со стеммингом `src/agent/stem.py`). `VectorStore.search_hybrid` — объединяет BM25 и векторный через RRF (Reciprocal Rank Fusion). Гибрид находит и точные термины («16 ГБ»), и семантику («оперативная память»).

**Асинхронность.** Веб-сервер выполняет задачи агента через `asyncio.create_task` (не потоки); запросы к Ollama идут через асинхронный HTTP-клиент, а синхронные инструменты — в thread pool, чтобы не блокировать event loop. CLI использует синхронный путь.

## Ограничение hybrid search (C5)

BM25 в изоляции находит «Установка с нуля» по запросу «Как установить агента с нуля?» со score 8.766. Но `search_hybrid` возвращает «Как понять, что агент выбрал…» — потому что `mpnet-base-v2` ставит этот чанк vector top-1, а «Установка» не попадает в vector top-10. RRF использует ранги, не score — преимущество BM25 теряется.

Причина: семантическая близость «как установить» и «как понять, что агент…». Не размер корпуса (проверено на 94 и 3116 чанках — результат одинаковый).

Что работает: «требования к оперативной памяти», «16 ГБ», «как настроить OSPF» — находятся корректно.

Обход для пользователя: уточнять запрос — «по названию раздела», «что в документации про установку».

## Генерация документа по шаблону

Агент умеет создавать новые документы по структуре существующих — через `read_document` + `write_document`.

**Шаг 1.** Положите шаблон в `data/documents/template.md`:

```markdown
# Отчёт по проекту

## 1. Введение

Краткое описание проекта.

## 2. Цели и задачи

Список целей.

## 3. Результаты

Что достигнуто.

## 4. Выводы

Итоги.
```

**Шаг 2.** Запустите:

```bash
python -m agent run "Прочитай шаблон data/documents/template.md и создай по нему новый документ: отчёт по разработке AI-агента"
```

Что произойдёт (в логе `logs/agent.log`):

```
step=1 type=tool_call tool_name=read_document
tool read_document -> dict (path, text, truncated, total_chars, suffix)
step=2 type=tool_call tool_name=write_document
tool write_document -> dict (path, title, size_chars)
step=3 type=final
```

Результат: `data/generated/отчёт_по_разработке_ai-агента.md` — 4 секции как в шаблоне, содержание новое.

### Как это работает

- `read_document(path, max_chars=4000)` — читает документ, склеивает сегменты через `\n\n`, включает `## section` в текст (иначе шаблон теряет структуру). Защита от path traversal: путь должен быть внутри корня проекта.
- `write_document(title, content)` — обёртка над `save_note`: если `content` начинается с `# title`, дубль убирается (иначе получится два заголовка). Сохраняет в `data/generated/`.
- `SYSTEM_PROMPT` содержит правило: «после `read_document` сразу вызови `write_document` через tool_call, не пиши имя инструмента текстом».

### Ограничение 7B (C6)

Модель генерирует обобщённое содержание («Интеграция с CRM успешно завершена», «Создание базы данных»), не зная реального контекста проекта. Для точности — уточняйте в задаче конкретику:

```bash
python -m agent run "Прочитай шаблон data/documents/template.md и создай отчёт. Цели: локальность, RAG, 7B. Результаты: save_note, read_notes, search_documents."
```

## Пошаговый разбор: что происходит после запуска команды

Этот раздел — учебный. Он показывает путь от нажатия Enter до появления файла с заметкой.

### Команда, которую разбираем

```bash
python -m agent run "Сохрани заметку 'Тест запуска' с текстом 'Привет'"
```

### Разбор:

- `python` — интерпретатор.
- `-m agent` — запуск пакета `agent` (`src/agent/__main__.py`).
- `run` — подкоманда (одна задача).
- `"..."` — цель агента.

### Что происходит внутри

1. **`__main__.py` → `main()`.** Python читает `src/agent/__main__.py`, находит `if __name__ == "__main__": main()`. Параллельно импортируются `load_config`, `setup_logging`, `argparse`.
2. **`argparse`.** `parser.parse_args(["run", "..."])` → `args.command="run"`, `args.goal="..."`.
3. **`load_config()`.** Читает `config/settings.toml` от `_PROJECT_ROOT` (не от CWD). Возвращает `AppConfig(llm, paths, safety, rag)` — типизированный объект, не словарь.
4. **`setup_logging(config.paths.logs_dir)`.** Настраивает логгер `"agent"`: файл `logs/agent.log` (UTF-8, append) + консоль. Формат `время | уровень | имя | сообщение`. Защита от дубликатов обработчиков.
5. **`build_orchestrator(config, logger)`** (из `src/agent/app.py`):
   - `tools = build_tools(config)` — список из 11 инструментов. `search_documents` создаётся фабрикой `make_search_documents_tool(config)` (ленивая загрузка `VectorStore` + `Embedder` в замыкании), остальные — модульные константы.
   - `registry = ToolRegistry()`; `for tool in tools: registry.register(tool)`.
   - `llm = OllamaLLM(model=config.llm.model, base_url=..., tools=tools, ...)`.
   - `tool_context`: для инструментов с `needs_notes_dir=True` — `{"notes_dir": config.paths.notes_dir}`; с `needs_output_dir=True` — `{"output_dir": config.paths.generated_dir}`; с `needs_trash_dir=True` — `{"trash_dir": config.paths.trash_dir}`. `search_documents` и `read_document` — без контекста.
   - Возвращает `Orchestrator(llm, registry, logger, max_steps, tool_context, max_tool_failures)`.
6. **`cli.run_once(goal, config, logger)`** → `_run_one(service, goal, logger)` → `service.ask(goal)` → `orchestrator.run(goal)`. В `run` (одиночная задача) история диалога пустая; в `chat` и веб-чате в `run` передаётся `history`.
7. **`Orchestrator.run(goal, history=...)`:**
   - `messages = [{"role": "system", ...}] + sanitize_history(history) + [{"role": "user", "content": goal}]`. Санитария истории: только роли `user`/`assistant`, последние 10 сообщений, суммарно до 4000 символов, обрезка длинных реплик — защита контекста 7B.
   - Цикл до `max_steps`:
     - `response = self.llm.chat(messages)` — POST в Ollama (`/v1/chat/completions`).
     - Если `type="final"` и `content` не пустой — вернуть `OrchestratorResult(success=True, final_answer=..., steps_used=step)`. Если пустой — `success=False, error="empty final answer"`.
     - Если `type="tool_call"`:
       - `extra = self.tool_context.get(tool_name, {})`.
       - `arguments = {**response.tool_arguments, **extra}` — контекст перекрывает аргументы модели (защита от prompt injection).
       - `call_key = _make_call_key(tool_name, arguments)` — канонический JSON аргументов (порядок ключей и представление Path не влияют) для детектора повторов.
       - Если `call_key in executed_calls` → `SKIPPED`; если `failed_calls[call_key] >= max_tool_failures` → `ERROR (giving up)`; иначе — `registry.call(tool_name, **arguments)`.
       - Результат инструмента сериализуется в JSON-совместимый вид (`_serialize_tool_result`: Path → POSIX-строки, `None` → `null`) и попадает в `tool_results`.
       - `messages += [assistant(tool_call), user(tool_result)]` (с `SUCCESS` / `ERROR` / `SKIPPED`). При `ERROR` текст зовёт модель исправить аргументы и повторить.
     - Если цикл кончился без финала — `raise MaxStepsExceeded`.
8. **`ToolRegistry.call("save_note", title=..., content=..., notes_dir=...)`.** Находит `ToolDefinition` по имени, вызывает `func(**kwargs)`.
9. **`save_note(title, content, notes_dir, category=None)`** (из `src/agent/tools/save_note.py`):
   - Пустой `title` → `ValueError`.
   - `validate_category(category)` — защита от `..`, `/`, зарезервированных имён Windows.
   - Каталог: `notes_dir` или `notes_dir/<категория>`; `mkdir(parents=True, exist_ok=True)`.
   - Slug: lower, пробелы → `_`, удаление `<>:"/\|?*` и управляющих, сохранение Unicode, обрезка до 100, `rstrip(" .")`, экранирование Windows-зарезервированных (`CON`, `NUL`, `COM1..9`) префиксом `_`.
   - Поиск свободного имени: `slug.md`, `slug_1.md`, … — никогда не перезаписывает.
   - Запись `# {title}\n\n{content}\n` в UTF-8.
   - Возвращает `{"path": относительный путь, "title": ..., "category": ...}`.
10. **Второй запрос к модели.** `messages` содержит `tool_result: SUCCESS. save_note returned: ...`. Модель отвечает `type="final"`.
11. **`_run_one` печатает:**

```
Готово: Заметка сохранена.
Шагов: 2
Результаты инструментов: [{'path': 'тест_запуска.md', 'title': 'Тест запуска', 'category': None}]
```

12. **На диске:**
    - `data/notes/тест_запуска.md` — с `# Тест запуска\n\nПривет`.
    - `logs/agent.log` — `step=1 type=tool_call`, `tool save_note -> dict`, `step=2 type=final`, `final: ...`.

## Что важно понять

- **Агент — это цикл, а не один запрос.** Модель вызывается минимум дважды: чтобы выбрать инструмент и чтобы подтвердить финал.
- **Модель не пишет код и не трогает файлы напрямую.** Она возвращает «запрос на вызов», остальное делает Python.
- **Контекст инструментов — это защита.** Модель не знает, куда сохранять файлы. Путь приходит из конфига через `needs_notes_dir` / `needs_output_dir` / `needs_trash_dir`.
- **Три линии защиты от зацикливания:** системный промпт, детектор `executed_calls` (для успешных повторов), счётчик `failed_calls` (для падающих).
- **Память диалога — не память модели.** История не хранится в модели: код подмешивает предыдущие реплики в контекст каждого нового запроса (`sanitize_history`), поэтому модель остаётся stateless, а память переживает перезапуск сервера (веб) или живёт до выхода (CLI).
- **Логи — главный инструмент отладки.** Полные тексты заметок и документов в лог не пишутся, но тип ответа, имя инструмента и статус — видны.
- **Медленно — это нормально.** На CPU 7B-модель генерирует 2–5 токенов в секунду.

## Проблемы и решения

### `ollama: command not found`

Ollama не установлен или терминал не видит его. Переустановите Ollama и откройте новый терминал.

### `ConnectionError` при запуске агента

Ollama не запущен. Выполните `ollama serve` в отдельном терминале.

### Модель отвечает очень медленно

Это нормально для CPU. 7B-модель генерирует 2–5 токенов в секунду. Один запрос по документам — 2–4 минуты. Если критична скорость — переключитесь на 3B (см. раздел «Выбор модели»).

### Первый запрос в сессии очень долгий (>5 минут)

Холодный старт: Ollama загружает модель в память. Повторите запрос — следующие ответы пойдут заметно быстрее.

### `does not support tools` или модель не вызывает инструменты

Убедитесь, что используете `qwen2.5-7b-agent` (созданную через `Modelfile.7b`), а не `qwen2.5:7b`. Если не помогает — проверьте версию Ollama: `ollama --version`. Обновите, если старше полугода.

### `ModuleNotFoundError` при запуске pytest

Виртуальное окружение не активировано. Активируйте (см. шаг 4) и повторите. Если активировано, но ошибка остаётся — проверьте, что в корне есть `pyproject.toml` с `[tool.pytest.ini_options] pythonpath = ["."]`.

### `FileNotFoundError: config/settings.toml`

Вы не создали локальный файл настроек. Вернитесь к шагу 6. В сообщении об ошибке будет указан точный путь, по которому искали.

### `FileNotFoundError: index not found at ...`

Вы вызвали `search_documents` или `search`, но RAG-индекс не собран. Соберите: `python -m agent index --reset`.

### `SyntaxError: source code string cannot contain null bytes` в тестах

Файл повреждён (часто — сохранён в UTF-16). Проверьте кодировку в VS Code (в статус-баре должно быть UTF-8), при необходимости «Save with Encoding → UTF-8». Проверить, что в файле нет нулевых байтов:

```powershell
Get-ChildItem -Recurse -Filter *.py src, tests | ForEach-Object {
    $bytes = [System.IO.File]::ReadAllBytes($_.FullName)
    $nulls = ($bytes | Where-Object { $_ -eq 0 }).Count
    if ($nulls -gt 0) { Write-Host "$($_.FullName): $nulls nulls" }
}
```

### Тесты падают, но агент работает

Возможно, окружение повреждено. Пересоздайте `.venv`: удалите папку, выполните `python -m venv .venv`, активируйте, `pip install -e .`.

### Хочу посмотреть, что делал агент

Откройте `logs/agent.log`. Там видны типы ответов, имена инструментов, краткие результаты. Полные тексты заметок и документов в лог не пишутся.

### Хочу изменить `max_steps` или `max_tool_retries`

Отредактируйте `config/settings.toml`:

```toml
[llm]
max_steps = 15

[safety]
max_tool_retries = 3
```

После правки — перезапустите агент.

### RAG находит не то, что нужно

- Проверьте, что индекс собран и не пустой: `python -m agent search "запрос" --top-k 5`.
- Если retrieval находит мусор — проблема в chunking или эмбеддингах. См. `TODO.md` про C5 (vector доминирует на семантически близких запросах).
- Для точных терминов (номера, аббревиатуры) BM25 справляется лучше, чем векторный. Если запрос семантический («что написано про установку») — попробуйте точную формулировку из документа.
- Если веб-поиск возвращает старые результаты после переиндексации — перезапустите `python -m agent web` (T41).

### Поиск по заметкам не находит слово, которое точно есть в тексте

Ограничение стеммера (C10): префикс 5 символов всей строки запроса. «Единый контракт» не находит «единого контракта» (префиксы «едины» ≠ «едино»). Обход: формулируйте запрос словом из текста — «контракт» найдёт «контракта».

### `python -m agent` не работает, `python -m src.agent` работает

Не выполнен `pip install -e .`. Выполните (см. шаг 5) или используйте `python -m src.agent`.

## Известные ограничения текущей версии

- **Скорость 7B на CPU.** Один вопрос по документам — 1.5–4 минуты. 3B быстрее, но путает `search_documents`/`search_notes` и иногда выдаёт пустые ответы. См. «Выбор модели».
- **C5: hybrid search доминируется vector на семантически близких запросах.** «Как установить агента?» → «Как понять, что агент…», а не «Установка». Причина — `mpnet`, не размер корпуса. См. раздел «Работа с документами».
- **C6: 7B галлюцинирует в содержании при генерации по шаблону.** Заполняет секции типичными фразами («Интеграция с CRM»), не зная реального контекста проекта. Обход — уточнять конкретику в задаче.
- **C7: 7B возвращает 2 `tool_calls`, используется первый.** Второй теряется. Для текущих задач не блокер.
- **C9: 7B передаёт заголовок заметки вместо пути в `update_note`/`move_note`/`delete_note`.** Инструменты переживают это через фолбэк по заголовку; при нескольких совпадениях заголовков вернут список кандидатов.
- **C10: стеммер не склеивает многословные запросы и некоторые словоформы.** Обход: однословные запросы словом из текста. См. `TODO.md`.
- **C1: изредка модель пишет `tool_call: ...` текстом внутри финального ответа** (имитация формата истории), обычно после ошибки инструмента. Лечится инженерно, не промптом; см. `TODO.md`.
- **T41: запущенный веб-сервер не подхватывает новый RAG-индекс после переиндексации** — держит старый `VectorStore` в памяти до перезапуска. Обход: перезапуск `python -m agent web`; чинится вместе с этапом C.
- **Память диалога ограничена:** последние 10 сообщений, суммарно до 4000 символов (веб) / 20 сообщений (CLI) — защита контекста 7B от переполнения. Долговременной памяти между сессиями нет.
- **Галлюцинации на неполных запросах.** На «Запиши заметку в файл» без содержания модель может придумать заголовок. Промпт `save_note` просит уточнения, но на 7B галлюцинация не устранена полностью.
- **RAG работает на Markdown, TXT, PDF, DOCX.** HTML, EPUB — в планах.
- **Скан-PDF не извлекается.** PDF без текстового слоя (сканы) пропускается; нужен OCR (отдельный шаг).
- **Один инструмент за шаг.** Для двух действий — два запроса.
- **Индекс RAG не инкрементальный.** Любое изменение корпуса — `python -m agent index --reset`.
- **`ask` отвечает из pretrained-знаний, может ошибаться.** 7B на общих вопросах не эталон (например, путает литературные направления). Для точных фактов — 13B+ или облачная модель.
- **Web UI без аутентификации.** Доступен по локальной сети любому. Не открывать в интернет. См. «Безопасность».

## Безопасность

Агент работает в изолированной среде. Никакие данные не отправляются в интернет: ни документы, ни заметки, ни запросы к модели. Ollama работает на `localhost`.

**Web-интерфейс доступен по локальной сети без аутентификации.** Любой, кто находится в вашей локальной сети, может открыть `http://<ip>:8000` и пользоваться агентом: читать заметки, искать документы, создавать файлы. Это осознанное решение для pet-проекта в доверенной сети.

**Не открывайте порт 8000 в интернет.** Не делайте port forwarding на роутере. Если нужен удалённый доступ — используйте VPN (WireGuard, Tailscale) или SSH-туннель, а не публикацию порта.

Если требуется минимальная защита в локальной сети — можно добавить токен в заголовке `X-Agent-Token` (проверка в middleware, 30 минут). См. `TODO.md`, C8. Пока не реализовано.

**История диалога приходит из браузера** и обрабатывается как недоверенные данные: принимаются только роли `user`/`assistant`, лишнее отбрасывается, объём ограничен (см. «Известные ограничения»). Чужие роли (`system`, `tool`) отклоняются на уровне валидации запроса.

## Лицензия и приватность

Проект работает локально. Никакие данные не отправляются в интернет. Модель, документы и логи остаются на вашем компьютере.

PyMuPDF (`pymupdf`) распространяется под AGPL. Для pet-проекта и локального использования это не проблема; для коммерческого распространения — нужна коммерческая лицензия Artifex или замена на `pypdf` (MIT).
