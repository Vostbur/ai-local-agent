## 📌 Оптимизация скорости 7B (после 7.1.4)

Сейчас 7B на CPU — 1.5–4 минуты на вопрос. Терпимо для «раз в день», но мешает интерактивному использованию. Варианты по возрастанию усилий:

- [ ] **Интерактивный режим для серии вопросов.** Модель остаётся в памяти между вопросами. Уже есть (`run_agent.py` без аргументов). Достаточно не выходить после каждого вопроса — экономит 30–60 с на загрузку модели. **0 усилий.**
- [ ] **`num_ctx=4096` вместо 8192.** −5–10% по скорости, −1 ГБ RAM. Меняется одна строка в `Modelfile.7b`. **5 минут.**
- [ ] **`max_tokens=256`.** Обрезка длинных ответов 7B. Меняется одна строка в `config/settings.toml`. **5 минут.** Осторожно: если ответ не помещается — модель может обрывать мысль.
- [ ] **`Q4_0` вместо `Q4_K_M`.** −10–15% по скорости, чуть хуже качество. Пересборка модели через `Modelfile.7b` с `FROM qwen2.5:7b` + нужный тег. **10 минут.**
- [ ] **`llama.cpp` вместо Ollama.** −20–30% по скорости. Смена `base_url` в конфиге (`http://localhost:8080` вместо `:11434`) + запуск `llama-server` с моделью. **2–3 часа** (установка, конвертация, тесты). Шаг 9, но может быть приоритизирован.

Суммарно `num_ctx=4096` + `max_tokens=256` + `Q4_0` дадут ~20–30% экономии без смены бэкенда.
