## 🧩 Известные компромиссы (не баги)

### C1. Самодельный формат `tool_call:` / `tool_result:` вместо OpenAI `role: "tool"`
Для малых моделей стандартные роли часто работают хуже. На 7B можно пересмотреть — если решитесь на `llama.cpp` / OpenAI-совместимый бэкенд (шаг 9), сравнить оба формата. Пока — оставляем.

### C2. Стемминг: `query[:-2]` в `_search.py`, без стемминга в BM25
В `_search.py` (заметки) — эвристика `query[:-2]`. В `BM25Index` (документы) — токенизация без стемминга: «установить» ≠ «установка». Оба — осознанные компромиссы.

- Для заметок хватает `query[:-2]` — маленький корпус, предсказуемые заголовки.
- Для BM25 без стемминга — провал на «Как установить агента?» (раздел «Установка» не находится лексически, вытягивает только векторный поиск). **7.1.4** — унифицированный стеммер для BM25; после него можно применить и к `_search.py` (закроет T28).

### C3. Один tool call за шаг
Мультитул — после того, как конфиг и статусы станут однозначными. На 7B нет сигналов, что это критично: 7/7 routing в контрольном прогоне, синтез по 5 чанкам работает.

### C4. Дублирование списка инструментов — закрыто частично
T15 ввёл `ALL_TOOLS` в `app.py`. Но `TOOLS_WITH_NOTES_DIR` — второй список имён для `tool_context`. Полное закрытие — T30 (`needs_notes_dir` на `ToolDefinition`). Пока: «закрыто для `ALL_TOOLS`, не закрыто для `tool_context`». `search_documents` в `TOOLS_WITH_NOTES_DIR` не входит — правильно, ему `notes_dir` не нужен.

### C5. Гибридный поиск: vector доминирует на семантически близких запросах
На корпусе 3116 чанков (после добавления PDF) запрос «Как установить агента с нуля?» всё ещё возвращает «Как понять, что агент выбрал…», а не «Установка с нуля». BM25 в изоляции находит «Установка» со score 8.766, но RRF использует ранги, не score: vector top-1 «Как понять» перевешивает.

**Причина:** `mpnet-base-v2` семантически не различает «как установить агента» и «как понять, что агент…». Размер корпуса не влияет — на 94 и на 3116 чанках результат одинаковый.

**Что работает:** «требования к оперативной памяти», «16 ГБ», «как настроить OSPF» — находятся корректно.

**Возможные решения** (отложить):
- Смена эмбеддинга на `intfloat/multilingual-e5-small` с префиксами `query:`/`passage:` — 10–20 строк + переиндексация 3116 чанков (~5–10 минут).
- Cross-encoder реранкер после RRF — тяжелее, на CPU медленно.
- Взвешенный RRF с логарифмом BM25-score — не решает (проверено арифметикой).

**Когда вернуться:** если пользователь явно скажет «поиск по установке не работает» или появятся другие семантически близкие провалы. На 3116 чанках — не блокер.

## 📌 Оптимизация скорости 7B (после 7.1.4)

Сейчас 7B на CPU — 1.5–4 минуты на вопрос. Терпимо для «раз в день», но мешает интерактивному использованию. Варианты по возрастанию усилий:

- [ ] **Интерактивный режим для серии вопросов.** Модель остаётся в памяти между вопросами. Уже есть (`run_agent.py` без аргументов). Достаточно не выходить после каждого вопроса — экономит 30–60 с на загрузку модели. **0 усилий.**
- [ ] **`num_ctx=4096` вместо 8192.** −5–10% по скорости, −1 ГБ RAM. Меняется одна строка в `Modelfile.7b`. **5 минут.**
- [ ] **`max_tokens=256`.** Обрезка длинных ответов 7B. Меняется одна строка в `config/settings.toml`. **5 минут.** Осторожно: если ответ не помещается — модель может обрывать мысль.
- [ ] **`Q4_0` вместо `Q4_K_M`.** −10–15% по скорости, чуть хуже качество. Пересборка модели через `Modelfile.7b` с `FROM qwen2.5:7b` + нужный тег. **10 минут.**
- [ ] **`llama.cpp` вместо Ollama.** −20–30% по скорости. Смена `base_url` в конфиге (`http://localhost:8080` вместо `:11434`) + запуск `llama-server` с моделью. **2–3 часа** (установка, конвертация, тесты). Шаг 9, но может быть приоритизирован.

Суммарно `num_ctx=4096` + `max_tokens=256` + `Q4_0` дадут ~20–30% экономии без смены бэкенда.

## 📌 Уроки

### Правки промптов без теста теряются

**Правило:** любая правка промпта (описание инструмента, `SYSTEM_PROMPT`, `parameters.title.description`) сопровождается тестом на наличие / отсутствие ключевой фразы. 3 строки теста — дёшево, ловит регресс.

### Дефолты в двух местах — источник багов
`RAGConfig` содержал правильные дефолты, а `load_config` — старые (`MiniLM`, `800`). Пользователь без `[rag]` в TOML получал не то, что обещает документация. Исправлено через `RAGConfig()` в `load_config`.

**Правило:** дефолт — в одном месте. `load_config` берёт из датакласса (`rag_defaults = RAGConfig()`), а не хардкодит.

### Урок: тесты на «неизвестный X» используют гарантированно неизвестный X
Три раза за сессию тест падал после добавления нового формата, потому что использовал «пока неизвестное» расширение:

1. `test_extract_text_unknown_suffix_returns_none` — `.pdf` → `.xyz` (7.4).
2. `test_ignores_unknown_extensions` — `.pdf` → `.xyz` (7.4).
3. (потенциально) `.docx` в 7.4.1, `.html` в 7.4.2 — снова упадёт, если не заменить заранее.

**Правило:** тесты на «неизвестный X» используют `.xyz`, `.bin`, `.nonexistent` — расширения, которых **никогда** не будет в реестре. Не `.pdf`, `.docx`, `.html` — они «пока неизвестны», но станут известны.

### U5. Веб-интерфейс (FastAPI + SSE + HTMX) — 2–3 часа
**Приоритет:** после U4.
**Что:**
- `src/agent/web/app.py` — FastAPI-приложение.
- `GET /` — одна HTML-страница: поле ввода, чат, панель «индекс: 3116 чанков, модель: 7B, статус».
- `POST /ask` — принимает цель, возвращает `task_id`.
- `GET /stream/{task_id}` — SSE: `event: step` (прогресс), `event: final` (ответ).
- `POST /index` — кнопка «переиндексировать» с SSE-прогрессом.
- Jinja2 + vanilla JS `EventSource` (или HTMX). Без React/Vue — для одной страницы оверкилл.
- Запуск: `python -m agent web` (порт 8000, только `localhost`).
**Почему SSE, а не обычный HTTP:** 7B на CPU отвечает 2–4 минуты, браузер закроет соединение по таймауту. SSE держит соединение, показывает «ищу в документах → нашёл 5 фрагментов → генерирую ответ → готово». Не требует стриминга Ollama — прогресс по шагам оркестратора уже полезен.
**Безопасность:** только `localhost`. Если открывать в локальной сети — предупредить в README, что любой в сети может пользоваться. Не выставлять в интернет.
**Зависимости:** `fastapi`, `uvicorn`, `jinja2` (~10 МБ). Добавить в `requirements.txt`.
**Не входит:** стриминг токенов (посимвольный вывод) — это шаг 9, требует `stream=True` в Ollama и SSE `event: token`. Аутентификация, история диалогов, множественные пользователи — не в этом шаге.
