## 🧩 Известные компромиссы (не баги)

### C1. Самодельный формат `tool_call:` / `tool_result:` вместо OpenAI `role: "tool"`
Для малых моделей стандартные роли часто работают хуже. Наблюдаемый побочный эффект: изредка модель пишет `tool_call: tool_name({...})` текстом внутри финального ответа (зафиксировано 2026-10-30). Пока — оставляем.

### C2. Стемминг: `stem.py` (префикс 5 символов), не `pymorphy3`
Префикс 5 символов решает задачу точнее для коротких текстов. **Ограничения:** короткие слова не трогаются; см. также C10 (многословные запросы и падежные формы).

### C3. Один tool call за шаг
Мультитул — после того, как конфиг и статусы станут однозначными. На 7B нет сигналов, что это критично.

### C5. Hybrid search доминируется vector на семантически близких запросах
**Причина:** семантика `mpnet`, не размер корпуса.
**Обход:** уточнять запрос. **Возможные решения (отложить):** e5-small, cross-encoder реранкер, взвешенный RRF.
**Приоритет:** низкий.

### C6. 7B галлюцинирует в содержании при генерации по шаблону
**Обход:** уточнять конкретику в задаче. В UI (этап D) — предупреждение «проверьте факты».
**Приоритет:** низкий.

### C7. 7B возвращает 2 tool_calls, используется первый
`OllamaLLM` берёт первый `tool_call` (T9). Второй теряется. Связано с C3.
**Приоритет:** низкий.

### C8. Изоляция и LAN без аутентификации
Web UI доступен по `0.0.0.0` (вся локальная сеть). Аутентификации нет. Модель, документы, заметки — на компьютере пользователя, в интернет ничего не уходит.
**Осознанное решение:** pet-проект, доверенная локальная сеть. Не открывать порт 8000 в интернет.
**Если понадобится защита:** токен в заголовке `X-Agent-Token` (проверка в middleware, 30 минут).

### C9. CRUD-инструменты принимают заголовок вместо пути (фолбэк)
**С 2026-10-31 — осознанное поведение, не баг.**
7B устойчиво передаёт заголовок заметки вместо пути и не восстанавливается после ошибок (см. TASKS.md, C9). `resolve_note_file` резолвит заметку по заголовку/базовому имени: уникальное совпадение используется, несколько — ошибка со списком кандидатов.
**Границы фолбэка:** `path` остаётся основным контрактом; при неоднозначных заголовках агент получит список кандидатов и должен передать точный путь.
**Риск принят:** удаление по совпавшему заголовку перемещает файл в корзину (восстановимо), поэтому фолбэк применён и к `delete_note`.

### C10. Стеммер: многословные запросы и падежные формы
«текст два» → стем всей строки «текст» → матчит всё с первым словом; «единый» ≠ «единого» (префиксы «едины»/«едино»).
**Обход:** запрос словом из текста. **Возможные решения (отложить):** стемминг по словам, префикс 4, `pymorphy3`.
**Приоритет:** низкий.

## 📌 Уроки

### Урок: `import pymupdf`, не `import fitz`
`fitz` — старое имя PyMuPDF, deprecated с 1.24. Проверять импорты библиотек, которые недавно переименовывались.

### Урок: тесты на «неизвестный X» используют гарантированно неизвестный X
`.xyz`, `.bin`, `.nonexistent` — расширения, которых никогда не будет в реестре.

### Урок: few-shot с синтаксисом вызова инструмента ломает routing
Слабые модели «подражают» формату как тексту ответа. Правило: новые правила промпта — текстом без `tool_name(...)`. Тест `test_system_prompt_does_not_contain_write_document_few_shot` и `test_system_prompt_no_call_syntax_for_crud_tools` страхуют.

### Урок: «7B копирует» ≠ «7B виновата»
Перед тем как винить модель, проверить в `logs/agent.log`, что именно ушло в `tool_result`.

### Урок: «documentation rot» — правки промптов без теста теряются
Любая правка промпта сопровождается тестом на наличие/отсутствие ключевой фразы.

### Урок: дефолты в двух местах — источник багов
Дефолт — в одном месте (датакласс), `load_config` берёт из него.

### Урок: реальные пути в примерах SYSTEM_PROMPT модель копирует вместо поиска (2026-10-30)
Пример `'тесты/тест_b1.md'` в правиле промпта совпал с реальной заметкой — модель копировала пример вместо вызова `list_notes`. Правило: в промпте только абстрактные форматы (`'категория/имя_файла'`), тест `test_system_prompt_does_not_contain_real_note_paths` страхует.

### Урок: поведение 7B после ошибки промптом не лечится — защита в инструменте (2026-10-30)
Три итерации промпта (правило «сначала путь», запрет угадывать, направляющая ошибка, текст «повтори») не заставили модель сходить в `list_notes` после ошибки — она сдавалась в финал. Рабочее решение — фолбэк резолва по заголовку в `resolve_note_file`. Правило: если поведение модели после ошибки стабильно плохое — переносить защиту в слой кода, не тратить итерации промпта.

### Урок: лимиты длины описаний инструментов существуют не просто так (2026-10-31)
Описание `read_notes` ограничено 400 символами (шаг 6.4, маршрутизация малых моделей). Расширения описаний проверять тестом до коммита; формулировать аддитивно и коротко.

### Урок: многословный запрос в стеммере вырождается в префикс первого слова (2026-10-31)
«текст два» матчит все заметки со словом «текст». В тестах поиска — однословные запросы или заведомо уникальные фразы; в документации — совет формулировать запрос словом из текста (см. C10).

### Урок: финал с текстом `tool_call:` — модель имитирует формат истории (2026-10-30)
Вариант C1: после ошибки модель «поняла» нужный шаг и написала `tool_call: list_notes({...})` текстом финала вместо реального вызова. Не лечить отдельно — закрыто фолбэком по заголовку.
