## Известные проблемы и наблюдения

### Модель qwen2.5-3b: нестабильный tool calling — решено переходом на 7B (шаги 6.1–7.5)
**Обнаружено:** 2026-10-25
**Закрыто:** 2026-10-29

**Симптомы (исторически):**
- Зацикливалась на повторных вызовах.
- Генерировала бессмысленный контент.
- Файлы сохранялись с суффиксами `_1.md`, `_2.md` из-за повторов.

**Причина:** 3B слишком мала для надёжного tool calling.

**Решение — 7B (7.5):** `qwen2.5-7b-agent` — routing 7/7, synthesis 6/7. Стоимость: скорость −2–3×, RAM ~6 ГБ. 3B — опция.

### RAG: качество поиска — итерации (шаги 7.1–7.2)
**Результат:** retrieval находит правильный раздел в 6/7 случаев. Оставшийся провал — C5.

### C5. Hybrid search доминируется vector на семантически близких запросах
BM25 в изоляции находит «Установка с нуля» со score 8.766. `search_hybrid` возвращает «Как понять, что агент…» — `mpnet` ставит этот чанк vector top-1.
**Причина:** семантика `mpnet`, не размер корпуса.
**Обход:** уточнять запрос. **Возможные решения (отложить):** e5-small, cross-encoder реранкер, взвешенный RRF.
**Приоритет:** низкий.

### C6. 7B галлюцинирует в содержании при генерации по шаблону
Заполняет секции типичными фразами («Интеграция с CRM успешно завершена»), не зная реального контекста проекта.
**Обход:** уточнять конкретику в задаче. В UI (этап D) — предупреждение «проверьте факты».
**Приоритет:** низкий.

### C7. 7B возвращает 2 tool_calls, используется первый
`OllamaLLM` берёт первый `tool_call` (осознанно, T9). Второй теряется. Связано с C3.
**Приоритет:** низкий.

### C9. 7B передаёт заголовок вместо пути в CRUD — закрыто фолбэком (этап B)
**Обнаружено:** 2026-10-30, три прогона.
**Симптомы:**
- Модель передаёт `'Тест B1'` / `'тесты/Тест B1'` / `'тесты/Тест B1.md'` в `path` вместо реального пути.
- После направляющей ошибки не восстанавливается: сразу финал («проверьте название», «используйте list_notes»), хотя `max_tool_failures` давал вторую попытку.
- В одной попытке написала `tool_call: list_notes({...})` текстом внутри финального ответа (имитация формата из истории сообщений — вариант C1).

**Что НЕ помогло (промпт-итерации):**
1. Правило «сначала list_notes/read_notes» в SYSTEM_PROMPT.
2. Запрет «НЕ угадывай путь по названию».
3. Направляющий текст ошибки и ERROR-текст «исправь и повтори».
4. Пример пути в промпте превратился в приманку: модель копировала `тесты/тест_b1.md` (пример), а не искала путь.

**Решение — инженерное:** `resolve_note_file` в `_search.py`: файла нет → поиск по заголовку → поиск по базовому имени последней компоненты (без `.md`). Ровно одно совпадение → используется; несколько → `FileNotFoundError` со списком кандидатов; ноль → направляющая ошибка.
**Урок:** поведение 7B после ошибки промптом не лечится — защита дублируется в слое инструментов.

### C10. Стеммер: многословные запросы и падежные формы
**Обнаружено:** 2026-10-31 (тесты и прогон этапа B3).
- Многословный запрос стеммится целиком: «текст два» → префикс «текст» → матчит все заметки, содержащие первое слово.
- Словоформы, где окончание меняет 5-й символ, не склеиваются даже в одиночном запросе: «единый» («едины») ≠ «единого» («едино») — поиск «единый контракт» по тексту «Проверка единого контракта» вернул 0.
**Обход:** формулировать запрос словом из текста («контракт» находит «контракта»).
**Возможные решения (отложить):** стемминг по словам, префикс 4 символа, пересмотр `pymorphy3`.
**Приоритет:** низкий.
